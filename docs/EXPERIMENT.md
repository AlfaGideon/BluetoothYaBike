# Как снять протокол разблокировки Яндекс Байка (пошагово)

Цель: получить **свои** кадры Bluetooth-разблокировки, чтобы приложение могло повторять их
без интернета. Официальное приложение Яндекс Про делает это по BLE (подтверждено
разработчиками Яндекса: [dev.go.yandex/blog/yandex-bike](https://dev.go.yandex/blog/yandex-bike)),
но формат кадров не опубликован. Единственный надёжный путь — один раз записать трафик
своего байка.

> Делайте это только со своим байком и своим аккаунтом. Чужие байки, обход блокировок и
> изменение прошивки — это нарушение оферты (п. 4.7.18, штраф 5 000 ₽) и повод для бана.
> Всё, что ниже, — разбор обмена *вашего* устройства с *вашим* приложением.

---

## Часть 0. Что понадобится

| Что | Зачем |
|---|---|
| Телефон с Android 8+ | приложение BluetoothYaBike + официальный Яндекс Про |
| Байк, к которому привязан ваш аккаунт | трафик «свой» |
| Компьютер с `adb` (или телефон + приложение для чтения bugreport) | забрать `btsnoop_hci.log` |
| Python 3 | `tools/parse_btsnoop.py` |

Официальное приложение при «офлайн-разблокировке» само по себе не требует интернета —
поэтому записывать можно в самолётном режиме (мобильный интернет и Wi-Fi выключены,
Bluetooth включён). Так в лог попадёт только BLE-обмен с байком, без сетевого шума.

---

## Часть 1. Первичный осмотр байка нашим приложением

1. Установите APK из GitHub Actions (Actions → последний зелёный run → Artifacts).
2. Включите Bluetooth, откройте приложение, нажмите **Сканировать**.
3. Найдите байк: обычно имя содержит модель/номер (у курьерских байков встречаются
   имена вида `YB…`, `Bike…`, `MM…` — ориентируйтесь на RSSI: рядом с байком сигнал
   `-40…-60 dBm`).
4. Тапните по байку. В журнале появится:
   - `SERVICE …` — список сервисов и характеристик с флагами `R|W|N|I`;
   - `RX ← …` — значения читаемых характеристик (серийник, версия, возможно challenge).
5. Нажмите **Экспорт** → «Поделиться» → сохраните файл. Это снимок GATT и всех данных,
   которые байк отдаёт без авторизации. Он понадобится, чтобы понять, на какой
   характеристике «живёт» протокол (обычно это канал с `W|N` в одном сервисе).

Что важно зафиксировать в экспортированном файле:
- UUID сервиса с характеристикой, у которой есть одновременно запись и уведомления;
- меняются ли значения read-характеристик между подключениями (если да — это nonce/challenge,
  значит протокол динамический и просто «повторить кадр» не выйдет);
- MTU и длина кадров (длинные кадры = шифрование/подпись, короткие = команды).

## Часть 2. Запись трафика официального приложения

### 2.1. Включить HCI snoop log

**Автоматически из приложения (v0.4.0).** Кнопка **«Захват»**:
- показывает текущее состояние журнала HCI;
- включает его сама, если приложению один раз выдали право записи настроек:
  `adb shell pm grant ru.alfagideon.bluetoothyabike android.permission.WRITE_SECURE_SETTINGS`
  (после перезагрузки телефона право сохраняется, повторять не нужно);
- если на телефоне есть root — читает `btsnoop_hci.log` напрямую, вообще без отчётов;
- открывает одним тапом нужные экраны (Для разработчиков, Bluetooth, Яндекс Про).

Чего приложение сделать не может (ограничения Android, а не кода): включить Bluetooth без
запроса, запустить «Взять отчёт об ошибке» и прочитать чужой BLE-трафик. Эти три действия
системные — приложение доводит до них в один тап и делает всё остальное само.

Ручной вариант ниже — если права на настройки нет.


1. Настройки → **О телефоне** → 7 раз тапнуть по **Номер сборки** (включится режим разработчика).
2. Настройки → Система → **Для разработчиков** → включить **«Включить журнал Bluetooth HCI»**
   (на разных прошивках: «Enable Bluetooth HCI snoop log», «Журнал HCI Bluetooth»).
3. Выключить и снова включить Bluetooth (лог начнёт писаться заново).

### 2.2. Разблокировать байк официальным приложением

1. Включите авиарежим, затем отдельно включите **Bluetooth** (интернет выключен).
2. Откройте **Яндекс Про** → раздел аренды транспорта → ваш байк.
3. Нажмите разблокировку (ползунок с замочком). Дождитесь щелчка замка.
4. Подождите 15–20 секунд, заблокируйте байк (кнопка на руле) и разблокируйте ещё раз —
   второй цикл нужен, чтобы сравнить два обмена и понять, какие байты меняются.

### 2.3. Забрать лог — три способа

**Способ А (без компьютера, самый простой):** Настройки → Система → Для разработчиков →
**«Взять отчёт об ошибке»** (Take bug report) → дождаться уведомления → «Сохранить». Получится
zip-архив. Откройте его в BluetoothYaBike: **«HCI-лог» → «Выбрать zip или btsnoop»** — приложение
само найдёт `btsnoop_hci.log` внутри, покажет кадры и даст повторить запись одним тапом.

**Способ Б (ADB, если есть компьютер):**


```bash
adb bugreport bugreport.zip
unzip -j bugreport.zip '*/btsnoop_hci.log' -d .
```

**Способ В (по пути файла):** на части прошивок лог лежит открыто:

```bash
adb shell cat /etc/bluetooth/bt_stack.conf | grep BtSnoop   # узнать путь
adb pull /data/misc/bluetooth/logs/btsnoop_hci.log          # нужен root/adb root
```

> Важно: на Android 10+ путь `/sdcard/btsnoop_hci.log` больше не используется,
> а на некоторых прошивках (Pixel) файл появляется только после «Взять отчёт об ошибке».

## Часть 3. Разбор лога

```bash
python3 tools/parse_btsnoop.py btsnoop_hci.log --mac AA:BB:CC:DD:EE:FF --writes
```

`--mac` — адрес байка (виден в нашем приложении в списке устройств), `--writes` оставляет
только записи и уведомления. Скрипт сам найдёт LE-соединение и покажет таблицу:

```
   t,ms  op             handle  hex / ascii
    0.0  Write Command  0x0011  01 02 03  |...|
    1.5  Notification   0x0022  DE AD BE EF  |....|
```

Дальше — ключевые вопросы, от которых зависит, в каком виде переносить протокол:

1. **Один канал или несколько?** Все записи идут в одну характеристику или в разные?
2. **Есть ли handshake?** Например: `Read → Notification(challenge) → Write(response)`.
   Если да, посмотрите, меняется ли challenge между двумя разблокировками.
3. **Кадр фиксированный?** Сравните две разблокировки: если кадры идентичны —
   достаточно повторить их (это самый простой случай).
4. **Есть ли счётчик/время?** Если кадр меняется в нескольких байтах, проверьте, не
   timestamp ли это (последние 4–6 байт, растут на разницу во времени).
5. **Ответ байка.** Какое уведомление приходит после успешной разблокировки? Это «эталон успеха»,
   которое наше приложение должно уметь распознавать.
6. **Привязка к соединению.** Переподключитесь (новое LE-соединение) и повторите разблокировку:
   если кадры те же — протокол не привязан к сессии, повтор сработает из нашего приложения.

## Часть 4. Перенос в BluetoothYaBike

- **Сценарий A — статичный кадр.** Записываете `handle` и hex-кадр в `docs/PROTOCOL.md`
  и повторяете из приложения: «GATT» → выбрать характеристику → ввести hex → «Отправить».
- **Сценарий B — handshake с ответом.** Нужен код: в `BikeBleClient` уже есть журнал RX/TX;
  добавляется небольшая функция, которая ловит challenge из уведомления и формирует ответ.
  Всё, что нужно, видно в экспортированном журнале.
- **Сценарий C — кадр подписан ключом аккаунта/байка.** Без ключа из приложения Яндекс Про
  (он извлекается из APK/трафика HTTPS) повторить нельзя. Это ограничение честно фиксируем:
  приложение остаётся инструментом исследования, а не взломом.

После того как протокол известен, в приложении появляется кнопка «Разблокировать»,
которая работает без интернета: BLE-соединение → handshake → кадр → проверка уведомления.

## Часть 5. Если что-то не так

| Симптом | Что делать |
|---|---|
| В логе нет LE-трафика | HCI snoop включён до перезагрузки Bluetooth? Перезагрузите BT и повторите |
| `adb` не видит телефон | включите «Отладка по USB», подтвердите RSA-ключ на экране |
| Приложение не подключается к байку, ошибка 133 | закройте Яндекс Про (он держит соединение), подождите 5 с, повторите |
| Байк не найден | он мог заснуть; нажмите кнопку на руле или приложите телефон ближе |
| Кадры меняются каждый раз | протокол динамический: смотрите вопросы 2–4 части 3 |
