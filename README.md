# BluetoothYaBike

Android-приложение для исследования BLE-обмена с умным велосипедом Яндекс Байк (IoT-модуль)
и автоматической сборкой APK в GitHub Actions. Работает без интернета на телефоне:
всё, что делает приложение, — это Bluetooth (скан → GATT → кадры).

**Скачать APK (всегда свежий):**
<https://github.com/AlfaGideon/BluetoothYaBike/releases/latest/download/app-release.apk>

## Почему приложение не видит обмен официального приложения «в эфире»

Android не даёт одному приложению перехватывать Bluetooth-трафик другого: эфир — общая среда,
но доступ к чужим соединениям закрыт системой. Поэтому:

- **своё** соединение приложение видит полностью (скан, GATT, все TX/RX) — и может отправлять
  любые кадры;
- **чужое** соединение (Яндекс Про ↔ байк) можно получить только из системного HCI-лога
  (Настройки → Для разработчиков → «Журнал Bluetooth HCI»), который приложение теперь
  разбирает само: кнопка «HCI-лог» → выбрать bugreport-zip → посмотреть кадры и повторить.

Скан видит только устройства, которые **сейчас что-то передают в эфир**. Если байк уже
подключён к Яндекс Про или спит, его в списке не будет: закройте официальное приложение,
нажмите кнопку на руле байка или включите «Радар» и поднесите телефон ближе.

## Главное ограничение

В публичном доступе **нет** описания Bluetooth-протокола Яндекс Байка. Официальное приложение
Яндекс Про разблокирует байк по BLE без интернета (это подтверждают разработчики Яндекса),
но кадры авторизации/разблокировки генерируются в приложении и, скорее всего, привязаны к
аккаунту и конкретному байку. Поэтому:

1. Приложение сейчас — **инструмент исследования**: оно показывает, какие каналы GATT есть у
   байка, что он присылает в эфир и как реагирует на записи.
2. Чтобы получить кнопку «Разблокировать», нужно один раз снять трафик официального
   приложения (Android HCI snoop log) и перенести найденные кадры в проект — пошаговый план
   в [docs/EXPERIMENT.md](docs/EXPERIMENT.md), журнал наблюдений в [docs/PROTOCOL.md](docs/PROTOCOL.md).
3. Скрипт для разбора snoop-лога: [tools/parse_btsnoop.py](tools/parse_btsnoop.py)
   (`python3 tools/parse_btsnoop.py --selftest`).

### Про «универсальный ключ»

Его не существует. В официальном приложении кадр разблокировки выдаёт сервер под ваш аккаунт,
а байк проверяет подпись/счётчик; отличий «мастер-ключа», как в самокатах с дефолтным ключом
прошивки, публично не находили. Поэтому приложение не притворяется, что умеет разблокировать
любой байк: оно снимает обмен **вашего** байка и повторяет его офлайн.

Почему нельзя «просто написать приложение, которое разблокирует любой байк»: без записи
обмена своего байка неизвестны ни UUID канала, ни формат кадров, ни ключ/подпись. Любая
реализация «наугад» — это перебор, который проще и безопаснее сделать на своём байке,
а не заливать в публичное приложение.

| Сценарий после записи трафика | Что получится |
|---|---|
| Кадр фиксированный, без challenge | кнопка «Разблокировать» работает офлайн |
| Есть handshake (challenge/response) | нужен небольшой код разбора уведомления — всё видно в журнале |
| Кадр подписан ключом аккаунта/байка | офлайн-повтор невозможен без ключа; приложение остаётся исследовательским |

## Сборка

Автоматически: `.github/workflows/android.yml` (JDK 17, Gradle 8.11.1, AGP 8.7.3, Kotlin 2.0.21).

Локально:

```bash
./gradlew assembleDebug
adb install -r app/build/outputs/apk/debug/app-debug.apk
./gradlew testDebugUnitTest   # юнит-тесты hex-парсера и выбора канала
```

Требования: JDK 17 и Android SDK (compileSdk 35).

## Безопасность и правила

- Приложение не пишет в сервисы прошивки (DFU/OTA) при широковещательной отправке;
  вручную такую характеристику выбрать можно, но лучше не надо.
- Работайте только со своим байком и своим аккаунтом: оферта запрещает модификацию
  оборудования и ПО (п. 4.7.18, штраф 5 000 ₽), а за обход блокировок байк могут отключить.
- Журналы содержат MAC-адреса — при публикации отчётов об исследовании вырезайте их.
